Implementation
- App and admin JWT validation now requires exp, validates token version, and keeps app/admin signing keys and claims separate.
- User history authorization can query telemetry by its recorded pond snapshot and current farm owner.
- User alarm listing supports level, only_unconfirmed, limit, and offset before pagination in the provider query.
- Stats and pond status read all authorized alarms instead of fixed 200/5000 row caps; device tie-breaking is deterministic.
- Farm owner transfer locks and updates the farm in one transaction, validates the target user, and records farm.owner_changed audit metadata with actor and old/new owners.
- Admin resource errors map missing farms and ponds/rules to 404; batch confirmation remains transactional and rejects any missing or already-confirmed ID without partial writes.
- Admin pond filtering verifies farm existence; app device filtering verifies the requested pond is currently visible to the user and returns 404 otherwise. Invalid filter booleans and pagination values return 400.
