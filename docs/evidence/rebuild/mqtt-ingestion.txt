Implementation

- `internal/ingestion` is the application validation boundary for normalized events. It rejects invalid device identities, timestamps, unknown metrics, non-finite/out-of-range values, fractional signal values, malformed message IDs, and status events carrying property payloads.
- `internal/access` and `internal/core` consume the same metric range source. Access still applies protocol-specific filtering and ACL before dispatch; core validates again at the application boundary before persistence.
- `internal/ingestion/integration_test.go` drives the real core service against an isolated database and proves tenant attribution plus message-id deduplication.
