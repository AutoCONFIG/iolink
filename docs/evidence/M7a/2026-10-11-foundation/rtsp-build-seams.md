## Adversarial RTSP protocol fixture matrix

Use a deterministic loopback RTSP fixture server with two or more listeners: original source listener, a second listener within the configured allowed CIDR but with a different IP/port identity, and a denied listener. Each listener records accepted TCP connections and every RTSP request line/header; fixture responses can be selected per test. Use URI/user/password marker strings unique to the run. Start the hardened ZLM binary with isolated temp log directory, private API secret, API/HLS reachable only by the harness, all protocols/listeners disabled except those needed, log level at the most verbose supported level, and no proxy environment. Submit `addStreamProxy` through the private API with `retry_count=0`, then inspect listener captures, API response, stdout, and every generated log file.

| Case | Fixture response / event | Required assertion |
|---|---|---|
| Good baseline | OPTIONS, DESCRIBE with same-origin Content-Base and H264 SDP with relative `a=control:trackID=1`; SETUP and PLAY succeed. | Original listener sees expected handshake and playback; no alternate listener receives a connection; stream becomes available with H264. |
| Redirect to allowed target | Original responds to OPTIONS or DESCRIBE with 301/302 Location pointing to second listener that is inside allowed CIDR. | Request fails safely; second listener accepted connection count remains zero; logs/API error omit Location and source markers. |
| Redirect to denied target | 301/302 Location points to denied address. | Same fail-closed behavior; denied listener connection count remains zero. Include RTSP absolute and relative Location variants. |
| Foreign Content-Base | DESCRIBE 200 gives Content-Base at second listener; SDP uses relative track. | No SETUP/PLAY request reaches second listener and no credentials are sent there; request fails closed. |
| Foreign absolute session control | SDP `a=control:rtsp://<second>/...`. | No connection/request to second listener, no Authorization header leaves original origin; request fails. |
| Foreign absolute track control | Session control is `*` or relative, one media-level `a=control` points to second listener. | Same no-connection/no-credential assertion for the track path. |
| Same-origin controls | Same-origin Content-Base and relative session/track controls. | Normal SETUP/PLAY succeeds; confirms policy does not break supported relative controls. |
| Retry ownership | After initial success, fixture closes/reset connection; separately test an initial handshake failure. | ZLM does not initiate another TCP connection after failure/disconnect when retry_count=0. Then verify only an explicit application worker API call after fake current-policy revalidation creates a new attempt. |
| Leakage | Exercise success, redirect reject, malformed URI, auth challenge/failure, socket reset, and worker/API error with source/user/password markers; capture all verbose logs and API responses. | Search every stdout/file/API payload for raw URI, hostname/IP marker, username/password, Authorization value, SDP marker, and raw exception text: zero matches. Check URI-encoded and percent-encoded markers too. |

The design attachment already requires the redirect pair, foreign Content-Base/control, same-origin relative control, retry ownership, and logs across levels; this protocol matrix makes those requirements observable. Socket captures are necessary: inspecting URL strings alone does not prove there was no second connection. Repeat the RTSP request and reconnect after changing the fixture’s DNS answer to prove the worker-side path re-resolves and revalidates the target each time; provider-internal replay must not occur.
