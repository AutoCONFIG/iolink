# IoLink 实施计划 v3

版本：2026-09-19；状态：[双审过程与结论](PLAN-REVIEW-FINAL.md)。范围来源：本次用户明确要求 M0–M8 全部实施，按阶段交付。本文描述目标，不宣称当前实现通过验收。

## 1. 文档基线和范围

- 产品目标：智慧水产监测平台，覆盖设备采集、后台运营、小程序、报警、私有化交付与后续平台能力。
- 原始需求附件和两份历史基座评估报告不在仓库中。本版是基于现有文档及用户本次指令重建的需求基线；不再伪称逐字追溯缺失原稿。
- M0–M8 全部在实施范围内。买断先交付，订阅版后交付；多租户/RBAC 在 M6 中明确实施，不以客户量为是否开工的条件。
- 裸 TCP 私有协议不另建通用任意报文解析器：由网关固件转换到 MQTT 或 M8 的 Modbus TCP 适配交付，相关测试见 R47。OTA、第三方驱动市场、多数据库运行时切换不属于既定 M0–M8，不因此删除其他扩展项。
- 权威顺序：用户确认的范围 → 本计划与设计附件 → 版本化 API/MQTT 契约 → 验收台账。冲突必须修订并复审，不能用现有代码覆盖需求。代码是待审核实现。
- 唯一需求/验收台账为 [ACCEPTANCE.md](ACCEPTANCE.md)，唯一当前状态表为 [IMPLEMENTED.md](IMPLEMENTED.md)。其他速览只引用，不重复维护完成统计。

## 2. 架构边界

传感器/终端 → MQTT/HTTP/Modbus 适配 → iolinkd → 管理后台/微信小程序。

核心业务为 Go 单仓、单进程：access、core、appapi、adminapi、web/admin，领域契约放 internal/domain。PostgreSQL 16 + TimescaleDB 是配套数据库；生产入口使用 TLS 反代；M7 视频增加独立 ZLMediaKit 和 GB28181 信令适配。所谓“单二进制”仅指核心业务服务及嵌入管理前端，不包括数据库、反代、流媒体和小程序安装包。

管理前端固定 Vue3 + TypeScript + Vite + Element Plus，自建业务脚手架；不再同时指定与组件库不确定兼容的多种模板。小程序使用 uniapp + Vue3 + TypeScript；历史图采用 uCharts，安装版本在实施时锁定并记录兼容验证。参考仓库只作设计参考，不能计作本项目产物。

完整设计：[基础设计](PLAN-DETAILS.md)、[扩展设计](EXTENSIONS.md)、[部署与恢复](DEPLOY.md)。当前已发现的问题先修复，不重开无期限平台选型；阶段设计审查用于验证当前边界是否满足该阶段，不取消范围。

## 5. 规模与质量目标

基础容量目标：500 台设备，每分钟一条，约 72 万条/日；100 台约 14.4 万条/日。遥测保留 13 个月。容量验证使用 4 vCPU、8 GiB RAM、SSD、单数据库实例作为起始目标配置，记录数据库/Timescale/镜像精确版本。

R33 用 24 小时持续采集、同步 20 个历史查询客户端、90 天预置数据测试：正常网络零未解释丢失、历史/最新查询 p95 < 2 秒、错误率 < 0.1%、无持续增长队列。另计算 13 个月行数和实测单行/索引开销，给出磁盘预算及至少 30% 余量。未达标则优化/调整资源并复测，不将未经测试的“单实例绰绰有余”写成结论。

## 6. 审查与变更

需求、契约、数据库和 UI 变更在同一审查单中追溯到 Rxx。每阶段有自动测试、真实数据库集成及对应 UI/外部验证，不能只靠 fake。关键方案两位独立审阅员审同一版，无阻断项且明确通过才冻结。

本轮只修订实施文档和目标契约；历史 SQL、脚本及业务代码中的已知缺陷登记后在 M0 起修复，不能因文档更新而标为已实现。初审记录见 [PLAN-REVIEW-2026-09-19.md](PLAN-REVIEW-2026-09-19.md)。
