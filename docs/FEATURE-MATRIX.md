# 功能对照表(蜂鸟平台清单 vs IoLink 现状)

> 更新:2026-09-16 v2。
> **定位(重要)**:本项目目标是**商业化产品**。蜂鸟清单中的功能项(服务性质除外)视为
> **商业化基础需求**——即产品要卖,这些能力迟早要有;区别只在于先做后做。
> 因此判据从 v1 的"需求文档要不要"改为:**✅ 已实现 / ⏳ 已排期 / ❌ 未排期(= 基础需求的欠账,进路线图)**。
> 参照对象:upstream/hummingbird 的商业功能清单。

图例:✅ 已实现 · ⚠️ 部分 · ⏳ 已排期待做 · ❌ 未排期(商业欠账) · 🚫 战略不做 · n/a 非功能项

## 一、蜂鸟清单对照

| 功能 | IoLink | 说明 | 商业化优先级 |
|---|---|---|---|
| 设备接入 | ✅ | 内嵌 MQTT broker、token 一机一密、ACL、取值范围白名单(M1 验收) | 已达成 |
| 设备管理 | ✅ | 注册(密钥一次性发放)/列表/删除/在线状态,adminapi 全套 | 已达成 |
| 产品管理 | ⚠️ | 物模型固定水质终端;**多产品/物模型抽象未实现** | **高(商业化前置)**:卖平台必有多类设备 |
| 规则引擎-设备告警 | ✅ | 按池塘阈值、critical/warning 分级、未确认去重 | 已达成 |
| 规则引擎-数据转发 | ❌ | 第三方转发(HTTP/MQTT out) | **高**:政企/云平台对接是常见采购项 |
| 定时任务 | ❌ | 用户可配 cron(定时下发命令等) | 中 |
| 场景联动 | ❌ | 通用场景编排 | 中(告警已覆盖核心场景) |
| 告警中心 | ✅ | 两端 API 全;前端页面在 L2/L3 | 已达成(差前端) |
| 系统监控 | ✅ | /metrics(prometheus)+ /healthz;仪表盘随 L2 | 已达成(差 UI) |
| 告警通知 | ✅⏳ | WeChatNotifier 完成;真机实发等小程序凭据(M4) | 已达成(差联调) |
| OpenAPI | ⚠️ | /api/v1 + /admin/v1;**缺 API-Key/签名/限流的开放平台机制** | **高(商业化前置)**:对接方要开放凭证 |
| MQTT 协议接入 | ✅ | 核心接入方式 | 已达成 |
| HTTP 协议接入 | ❌ | HTTP 上报端点(≤1天) | 中:部分网关只支持 HTTP |
| TCP 协议接入 | ❌ | 裸 TCP 私有协议接入 | 低:用网关固件替代 |
| MODBUS 协议接入 | ❌ | 平台侧 Modbus 主站(直连 DTU 类设备) | **高(视硬件形态)**:若卖"平台+DTU"方案则必须;卖"平台+智能终端"则由固件承担 |
| 设备地图 | ❌ | 池塘/设备 GIS 定位 | 中:水产场景演示效果好 |
| 设备调试 | ❌ | Web 调试台(下发命令/查看原始报文) | 中:售前演示与现场排障利器 |
| 驱动市场 | 🚫 | 插件分发市场 | **战略不做**:与单程序轻量定位冲突;用"内置多协议"替代 |
| 网关接入 | ❌ | 网关+子设备两级拓扑 | 中:水产网关场景真实存在(一塘多探头) |
| 子设备接入 | ❌ | 同上(随网关接入一起) | 中 |
| 数据权限管控 | ⚠️ | 用户级隔离 + admin 独立 JWT;**缺多租户与细粒度 RBAC** | **高(商业化前置)**:卖给多个客户=多租户 |
| 多数据库支持 | 🚫 | 仅 PG/TimescaleDB,接口层留抽象 | **战略不做**:单栈是运维优势,不追蜂鸟多库卖点 |
| 数据报表 | ❌ | 历史数据导出/周期报表 | 中:政企客户常要 Excel/日报 |
| 一对一支持 | n/a | 服务性质 | - |
| 项目维护 | n/a | 自研自维护 | - |
| 定制化 | n/a | 自研天然可定制(相对蜂鸟"定制化仅旗舰版"是优势) | - |
| 数据大屏 | ❌ | 可视化大屏(参照 thingsvis) | 中:演示与政企验收利器 |
| 小程序 | ⏳ | /api/v1 全套已验收;uniapp 6 页面在 L3 线 | 已达成(差前端) |
| 视频设备接入 | ❌ | **摄像头/视频监控接入(GB28181/RTSP→流媒体)** | **高**:养殖场安防+可视化管理是采购标配 |
| 项目源码 | ✅ | 100% 自研,无黑盒 | 已达成 |

## 二、IoLink 独有/超出蜂鸟清单的功能

蜂鸟没有、我们已实现或设计内置的:

| 功能 | 状态 | 说明 |
|---|---|---|
| 领域数据模型(养殖场→池塘→设备) | ✅ | 通用平台只有"设备列表";我们原生支持按池塘组织、按池塘配阈值——养殖业务开箱即用 |
| 设备影子(device_shadows) | ✅ | 最新值常驻查询,实时页成本恒定;蜂鸟查询打时序大表 |
| 报警去重(未确认不重复触发) | ✅ | 防通知风暴;通用平台多依赖人工配静默期 |
| 双端 API 分离(/api/v1 与 /admin/v1) | ✅ | 小程序与后台独立 JWT 体系,天然多端安全边界 |
| 管理后台嵌入单二进制(go:embed) | ✅ | 一个文件交付整平台,部署=复制+起库 |
| Promethus 原生指标 | ✅ | 业务级指标(在线数/报警量/通知量)开箱可接 Grafana |
| 设备密钥一次性发放 | ✅ | 注册时明文仅返回一次,库中只有 sha256 |
| 微信订阅消息告警(配置驱动) | ✅⏳ | 蜂鸟无微信深度集成;我们告警直达养殖户微信 |
| TimescaleDB 时序+retention | ✅ | 蜂鸟开源版 SQLite/LevelDB 或 MySQL;我们原生时序能力+自动过期 |

## 三、商业化路线图(全量落地,不做选择性排期)

**决策:基础需求的欠账全部纳入正式计划**(详见 PLAN.md M6/M7/M8),不留"按需再做"的悬置项。
顺序安排只反映依赖关系(如网关接入先于子设备),不代表砍掉任何一项。

| 阶段 | 内容 | 对应蜂鸟功能项 | 承载里程碑 |
|---|---|---|---|
| P0 已完成 | 接入/管理/告警/通知/监控/双API/小程序接口 | 清单 11 项 ✅ | M0-M2、M5 |
| 商业化前置 | 多产品/物模型抽象、多租户+RBAC、OpenAPI 开放平台 | 产品管理、数据权限管控、OpenAPI | M6 |
| 行业标配 | 视频接入(GB28181/RTSP)、设备地图、数据大屏 | 视频、地图、大屏 | M7 |
| 增强能力 | 数据转发、HTTP 接入、Modbus 平台侧、定时任务、场景联动、网关+子设备、设备调试台、数据报表 | 其余全部 ❌ 项 | M8 |
| 进行中 | 小程序(M4)、管理后台(M3)联调交付 | 小程序 | M3/M4 |

契约先行原则不变:每个里程碑先出 openapi/设计文档再写实现。
