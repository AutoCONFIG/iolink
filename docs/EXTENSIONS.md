# 扩展能力设计与阶段关卡（M6–M8）

2026-09-19 目标设计；尚未实现。全部属于本轮授权范围。Rxx 对应 ACCEPTANCE.md；每个子阶段先提交完整 OpenAPI/DDL/页面规格，通过独立设计复核和契约校验后编码。这里固定跨阶段边界和可验收行为，具体库版本、寄存器表和真实账号在依赖表记录，不把未提供的外部输入当作已完成。

## M6a：产品和物模型（R34–R35）

- M6a先建立仅有default记录的tenants表作为外键基座，所有旧资源回填default；这不开放多租户。M6b再建立成员、隔离和多租户管理。products(id,tenant_id,name)、product_models(product_id,version,schema,published_at)，发布版本不可就地修改；设备固定 product_id/model_version。模型字段支持 number/integer/boolean/string，定义 identifier、单位、范围/枚举、可读/可写和 nullable；identifier 唯一且不得改变既有字段类型/单位。
- schema 变更新增版本；变更单位或类型须新 identifier，不覆写历史语义。设备升级显式执行并有审计，已入库历史记录 model_version。
- 保留水质 sensor_data 宽表和 /api/v1 五指标接口，水质注册为内置产品 v1。新增通用 telemetry(ts,device_no,pond_id,tenant_id,model_version,properties JSONB) hypertable，记录有效属性；数值查询白名单来自模型，不能将任意 identifier 拼进 SQL。
- 水质上报同时维护兼容宽表与通用数据，写入在同事务；旧数据迁移幂等回填且逐设备核对计数/区间/抽样值，迁移期间有高水位和切换记录，禁止双写造成重复计数。报表/动态 API 只读通用主数据，老 API 继续读兼容投影。
- 多产品报警去重键为(tenant_id,device_no,pond_id,product_id,metric_identifier)，仅约束未确认记录；model_version不入键，因为同identifier的类型/单位不允许改变。新identifier独立报警；调塘和跨产品重新配置不会被旧作用域报警压制。查询/插入/通知读取使用同一范围。
- 影子字段按属性合并，携带 model_version 和逐字段时间。缺失不清空，显式 null 仅在模型允许时清空；水质旧协议的 null 保持缺失语义。
- 新增 `/api/v2/devices/{no}/telemetry`、`/history?metric=...` 与管理 products/models/version/assignment 族契约；旧 v1 不要求前端升级，未知产品调用固定水质接口返回 400 unsupported product。
- 后台提供产品列表、字段编辑、发布版本、设备升级页；小程序动态详情按模型渲染可支持字段，不把 string 当曲线绘制。模型发布有前后端校验。
- 验收：第二种至少含数值与枚举的产品端到端；非法范围/字段拒绝或按已定字段丢弃规则处理并可观察；水质旧固件、v1 查询及报警回归；旧版本历史不受新模型修改影响。

## M6b：租户与权限（R36–R37）

使用 users 全局身份 + tenants + memberships(user_id,tenant_id,role,active)。一个微信身份可以属于多个组织，JWT 绑定当前 tenant_id，切换时重新签发并验证有效 membership；uid 不代表 tenant。单客户私有化安装也创建一个默认租户，许可证的 deployment_id 对应整个实例。

平台管理员是独立系统角色，仅管理租户开通/停用及授权，不自动读租户业务数据。租户管理员在本租户管理资源和成员；运维支持若需数据访问必须显式授予有时限的支持角色并审计，不用“全租户查询”绕过隔离。

| 主体 | 可读业务数据 | 写权限 | 不可越过的边界 |
|---|---|---|---|
| 平台管理员 | 默认无 | 租户生命周期、实例授权 | 需显式支持授权才能访问指定租户业务 |
| 租户管理员 | 本租户全部 | 农场/产品/设备/规则/用户分配/集成 | 不可创建平台管理员或跨租户改 owner |
| 操作员 | 被分配农场 | 确认报警、授权的设备命令 | 不可管理成员/Key/产品发布 |
| 只读成员 | 被分配农场 | 无 | 禁止确认/命令/导出配置 |
| 微信 USER | 自己拥有/被分配农场 | 报警确认；设备控制需额外显式授权 | 多组织身份必须选当前租户 |
| 第三方应用 | Key scopes + 本租户授权资源 | scope 明确列出的动作 | 不继承创建者全部权限 |

farms/products/devices/shadows/telemetry/alarms/rules/cameras/keys/jobs/commands/reports 均可追溯 tenant_id，写入校验父子同租户；唯一键除全局 device_no 外以租户限定。队列/outbox/调度/导出/播放鉴权携带 tenant_id 并在执行或下载时重验权限。查询必须先限定租户再限定农场，索引支持该条件。

旧库全部资源迁到默认租户，并生成 membership；记录关联清单与异常孤立资源，事务失败不部分开放。撤销 membership/角色或停租户立即拒绝新请求与未执行任务，通过权限版本避免旧 JWT 继续生效。后台增加组织/成员/角色页；casbin 管角色-资源-动作策略，数据库归属过滤不能被策略替代。

租户停用：登录/Key/播放/任务/采集均停止并记录审计，保留数据；平台管理员可恢复。License 过期策略不同，见下文，不能混用。

## M6c：License、首启和离线包（R38–R40）

- 文件为 `{payload_b64, signature_b64}`；payload 为 UTF-8 JSON 的原始字节，校验 RSA-PSS-SHA256 签名后再解析；包含 license_id、deployment_id、issued_at、not_before、expires_at（null 为永久）、max_devices、features、key_id。运行时仅内置/配置公钥，签发私钥留在独立离线签发工具与签发方，不进入镜像、仓库或客户端。
- 管理端导入/查询 License；导入校验签名、实例绑定、时间和字段，不因无效上传替换已有有效证书；记录摘要和审计。时钟最大已见时间持久化，倒退超过 5 分钟进入 clock_error 待核实，不能声称能对抗拥有主机 root 权限的篡改。
- 设备上限按实例内未停用设备计，网关和子设备各计一个；事务锁计数防并发超额，停用释放名额，恢复时重新检查。features 在 HTTP/MQTT/worker/页面对应动作统一检查，隐藏菜单不能替代服务端校验。

| 授权状态 | 既有采集/查询/报警 | 新增或恢复设备 | 可选功能与任务 | 管理恢复能力 |
|---|---|---|---|---|
| 有效/永久 | 正常 | 限额内允许 | 按 features | 可导入新证书 |
| 缺失/伪造/未生效/实例不符 | 保留已有数据读取、既有设备基础采集报警 | 拒绝 | 新可选操作和待执行控制任务拒绝 | 允许登录、备份、导入 |
| 过期/clock_error | 同上，不主动切断基础监测 | 拒绝 | 不启动新视频会话/导出任务/开放调用/控制；既有播放最长5分钟令牌到期；已开始备份/导出可结束 | 明确状态、恢复授权 |
| 降额后超限 | 既有基础服务保留 | 拒绝直到回到限额 | 仍按 features | 显示超额量，不自动删除设备 |

features 基础监测始终可用于存量恢复，其他值枚举 video/openapi/automation/reports。执行前重验授权；过期不得突然停止水质报警。初次安装无 License 只能配置账户、查看授权和导入，因无已注册设备不存在免费新增采集。

首启向导建立 deployment_id、管理员强密码、默认租户、License 和连接测试；不得公开默认 admin/admin123。离线包包括锁定镜像、核心二进制/前端、数据库/反代/可选流媒体、迁移、校验和、安装/卸载说明、测试工具。干净离线 Linux x86_64 + Docker Engine/Compose v2 已安装的验收机在30分钟内完成基础启动；下载包/准备Docker和长期历史恢复不计入此目标但须单独记录。ARM64 另建验收矩阵，未经构建测试不宣称支持。

## M6d：开放平台（R41–R42）

第三方只用 `/open/v1`，不复用管理员 JWT。Key 对应 tenant、scopes 和资源集合；创建返回 key_id 和 32 字节随机 secret 一次，secret 为 HMAC 验签需要在服务端用实例主密钥加密保存，不能只存不可还原摘要；日志脱敏，轮换产生新 Key、撤销旧 Key 立即失效。

请求头 X-Key-Id、X-Timestamp（Unix秒）、X-Nonce（至少128位随机）、X-Signature（小写hex）。签名原文为五行：大写 method、原始路径、规范查询串、时间戳、nonce，再第六行 SHA256(body) 小写hex；各行用 LF 连接、末尾无 LF。查询名和值按 UTF-8 RFC3986 编码后按编码后的键和值排序，重复参数保留，空值写 `key=`，禁止歧义编码及 `.`/`..` 路径。HMAC-SHA256(secret,原文)，恒时比较；阶段契约附固定测试向量。

允许时间差±300秒，成功鉴权 nonce 原子保存10分钟，重复返回401；错误签名不占用nonce。每Key令牌桶60次/分钟、burst10，按部署配置可调整，429 + Retry-After；多进程使用共享存储或明确单实例限制，不承诺独立内存桶的集群一致限流。已签名请求仍逐资源授权，跨租户404，scope不足403。后台有签发/轮换/吊销/日志页，文档含curl测试向量；拒绝重放、撤销、超速和越权都是退出条件。

## M7：视频、地图和大屏（R43–R45）

视频：RTSP 拉流和 GB28181-2016 注册/保活/目录/实时点播均在范围内，不含录像回放、云台/PTZ和国标级联。GB 信令由 iolinkd 的适配包负责，ZLMediaKit 负责媒体接入/转封装；设备目录关联 camera→pond→tenant。凭据加密存储，媒体地址由允许的网段/主机配置，禁止任意用户利用拉流访问未授权内网地址。

浏览器基线用 HTTPS HLS，支持 H.264/AAC；微信端在真机验证 live-player 支持及账号类目资质，不支持时在已验证环境提供可用播放方案，未验证不得宣称小程序视频完成。H.265仅可在支持转码且实测后声明支持，不属于基础兼容承诺。用户先经 API 授权获得5分钟播放令牌，媒体服务校验签名/租户/camera/到期；撤权或停租户停止会话，不能泄露源摄像机密码。详细端口、RTP范围、反代和网关鉴权在 M7a 的部署附件冻结；公网媒体入口未配置认证则拒绝开放。

地图：数据库保存 WGS84 经纬度；国内展示选择腾讯地图、转换至 GCJ-02 且标注转换边界，原始坐标不覆盖。Key按域名/AppID限制，开发用固定坐标 mock，生产需项目方提供Key。后台/小程序支持池塘与设备定位、点选详情、权限过滤；无坐标显示“未定位”，无Key/断网有明确错误而非空白成功。坐标编辑记录审计。

大屏：本租户只读统计API、10秒轮询、数据时间和离线提示；不提供匿名跨租户全局屏。读令牌只授数据读取、可吊销，后台配置布局但不执行用户脚本。测试20个并发屏、p95刷新<2s，与基础容量配置一起记录；大屏读数与同时间数据库查询一致。

## M8a：命令生命周期（R46）

commands(id,tenant_id,device_no,model_version,name,params,expires_at,state,idempotency_key,attempts,result)。API提交先查租户/农场/动作权限及物模型可写定义，同一调用方+idempotency_key重复返回原命令；下发 JSON 与 mqtt-spec.md 一致。

状态 queued→sent→succeeded/failed，或 queued/sent→expired；queued可取消，sent取消只能 best-effort 并明确可能已执行。默认TTL60秒，可选5..3600秒；设备离线则保留queued至过期，不伪造成功；worker重启继续持久任务，发送最多3次、间隔5秒且不得跨TTL。相同命令ID不重复执行的责任由设备实现并缓存24小时结果，平台接受重复同结果回执；旧固件无幂等能力不得自动重试物理动作。未知/非自身回执丢弃并审计；迟到回执保留审计，不把expired改成功。

控制是至少一次传输+端侧去重，不承诺物理执行 exactly-once。set_interval命令成功回执后更新设备report_interval，发出至确定结果间看门狗按新旧周期较大值执行，失败/过期保持原值；回执丢失但物理已生效时标配置待核实，由设备下一次有效状态上报/人工核实恢复一致，不能假定成功。模拟固件和真机分别验证成功、失败、断连、重复与重启。

## M8b：HTTP、Modbus、网关（R47–R49）

HTTP 上报 `/ingest/v1/devices/{no}/properties` 使用一机一密签名、时间窗和nonce，签名规范复用开放平台但凭据域独立；校验后的属性复用同一产品模型/存储/报警链，不旁路租户归属。device secret 为验签需新增加密存储用于支持HTTP的设备，迁移通过显式轮换获取，不能从已有SHA256反推；纯MQTT设备保留摘要路径。

Modbus 平台主站支持 Modbus TCP（DTU透明传输）与本机串口 RTU 两类部署；slave_id、function(03/04读取，控制06/16)、寄存器地址、数量、端序、scale/offset由产品适配配置定义。读写超时2秒，读取重试最多2次，失败标通信异常，不用旧值冒充新数据；写寄存器作为R46命令执行且不能盲目重试未知结果。硬件配置必须有型号/寄存器表和现场端口权限，软件模拟器可先完成。

网关使用自身凭据，子设备独立device_no/product/model/pond，同一租户，先登记 gateway_id↔sub_device_id 映射。新增 `iolink/up/{gateway_no}/sub/{sub_no}/properties` 和对应下行/回执；gateway ACL不仅检查topic前缀还查注册映射，不能把任意其他设备伪称子设备。子设备不直接拿网关secret连接；网关断线影响下挂设备在线状态，各子设备单独freshness/报警归属。

裸TCP私有传感器通过外部网关固件桥接到该MQTT契约，不提供未知报文自动识别。R47要有明确桥接样例和模拟报文/硬件验证，不将桥接描述成内置任意TCP服务器。

## M8c：转发、定时、联动、调试（R50–R53）

共用持久化 jobs/outbox，带tenant/资源/幂等键/attempts/lease/next_at；领取使用行锁/租约，重启后过期租约可接管，同一逻辑动作只建立一个job。执行前重新校验权限、租户状态和License，不能依赖创建时一次校验。

转发：按产品/设备/条件配置 HTTP webhook 或外部 MQTT，固定 envelope 含event_id/tenant标识/ts/payload；至少一次，接收端按event_id去重。指数退避1/2/4/8/16分钟后失败队列，人工重放沿用event_id。目标地址允许清单、TLS校验、凭据加密、重定向限制防止越过目标限制；面板显示投递状态和失败原因。

定时：cron五字段，时区固定Asia/Shanghai，最小1分钟。每次任务唯一(schedule_id,scheduled_at)；停机漏跑只补最近一次且最多滞后5分钟，其他记missed，禁用后不补；按命令TTL防陈旧控制。更新计划从下一分钟生效，夏令时问题由所选IANA时区库处理并测试，当前业务时区无DST。

联动：物模型比较条件 AND/OR，有连续命中时长和冷却期，动作仅R46命令或R50转发；版本化规则。检测规则依赖环，拒绝直接/间接循环；事件保留origin/depth，最大4跳，避免设备反馈造成无限触发。规则切换不追溯已处理历史，禁用后不启动新动作。

调试台：仅有权限的操作者可看脱敏原始报文、关联命令、回执与失败信息，不能显示secret/JWT/摄像机凭据；原始报文按租户限额保留24小时、单条64KiB，命令必须走R46权限和幂等路径，不设绕过验证的任意publish入口。

## M8d：报表（R54）

历史导出CSV/XLSX为异步任务，限定租户/农场/设备/指标/UTC区间，单任务最多100万行（超限拆分区间并返回400），顺序稳定，缺失值空单元格，单位和时间区明确。CSV对以=,+,-,@开头的文本做公式注入转义；数值保持数值类型，不能损坏合法负数。

日报用业务日Asia/Shanghai边界，按R52幂等调度；报表本身与下载链接都有tenant/owner校验，链接5分钟过期，文件保留7天后清理；转交/撤权后下载重验权限。失败可重试且结果不重复，页面有进度/错误/下载记录。验收以同区间数据库结果比对行数、边界时间、缺失值和统计值。
